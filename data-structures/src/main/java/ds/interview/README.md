# 모의 라이브 코딩 연습 기록

라이브 코딩은 "코드를 짜는 시험"이 아니라 **"생각을 말로 꺼내면서 짜는 시험"**이다.
여기에는 문제, 내가 말한 접근법, 막힌 곳, 피드백을 남긴다. 쌓이면 어디서 반복해서 막히는지 보인다.

## 매번 쓰는 틀

```
① 문제 되묻기     입력 범위? 비어 있을 수 있나? 동점이면? 기대 출력 형식?
② 예시 손풀이     주어진 예시를 손으로 따라가며 답 확인
③ 접근법 + 복잡도  "먼저 단순하게 O(n²)로, 그다음 개선" 식으로 말하기
④ 코드            중계하면서. 문법 틀려도 됨. 침묵만 피하기
⑤ 추적            예시 입력으로 코드를 한 줄씩 따라가기
⑥ 개선점          "실무라면 ~도 고려하겠습니다"
```

막혔을 때 할 말: **"지금 ~부분이 헷갈립니다. ~방향으로 생각 중인데 힌트 주실 수 있을까요?"**
→ 침묵 30초보다 이 한 문장이 훨씬 낫다.

## 반사적으로 나와야 하는 자료구조 짝

| 문제에서 이런 말이 나오면 | 바로 떠올릴 것 |
|---|---|
| "중복 제거", "이미 봤는지" | `Set` (`HashSet`) |
| "~별로 묶어서", "이름으로 찾아서" | `Map` (`HashMap`) |
| "개수 세기", "빈도" | `Map<K, Integer>` + `getOrDefault` / `merge` |
| "가장 큰 k개", "상위 N" | `PriorityQueue` (힙) |
| "순서대로 처리", "먼저 온 것부터" | `Queue` (`ArrayDeque`) |
| "괄호", "되돌리기", "가장 최근 것" | `Stack` (`ArrayDeque`) |
| "정렬된 상태 유지", "범위 검색" | `TreeMap` / `TreeSet` |
| "최단 거리", "몇 단계 만에" | BFS |
| "모든 경로", "연결돼 있나" | DFS |

## #1 — 가장 많은 페이지를 본 사용자  (`MostActiveUser.java`)

**문제**: `"사용자 페이지"` 로그 배열에서 서로 다른 페이지를 가장 많이 본 사용자. 중복 페이지는 1번.

**내가 말한 접근법**
공백으로 나누고 → 사용자별로 묶고 → 같은 페이지는 하나로 합치고 → 개수 세서 최대.
(흐름은 정확했음)

**막힌 곳**
- "같은 페이지를 하나로" 를 어떤 자료구조로 할지 → **Set** 이 바로 안 나옴
- `computeIfAbsent` 처음 봄 → 이름으로 추측해서 맞힘 (실무 코드에서 `containsKey` + `put` 형태로는 본 적 있음)

**잘한 것**
- 전체 흐름을 코드 전에 말로 정리
- 모르는 걸 모른다고 바로 말함
- "왜 반복문이 두 개냐" → "첫 번째 안에서는 Set이 다 안 채워져서" 정확히 답함
- 복잡도 O(n) 맞힘

**보완**
- 엣지 케이스(빈 배열, 동점)를 먼저 묻지 않음 → 면접관이 대신 꺼냄
- 문제에 없는 조건("숫자만 뽑아서 정규화")을 추가함 → 문제를 단순하게 보기

**다음 목표**: 코드 보기 전에 **엣지 케이스부터 묻기**

## #2 — 회의실 예약 겹침  (`MeetingOverlap.java`)

**문제**: `{시작, 종료}` 배열에서 겹치는 예약이 하나라도 있으면 true. 조건을 일부러 애매하게 냄.

**내가 한 질문**
- "4개인데 왜 boolean 하나?" → 출력 형식 확인. 좋은 질문.
- "딱 붙은 건 겹친 건가?" 를 **스스로 예상함** → 이게 핵심 질문. `<` vs `<=` 를 결정.
- 빈 배열 / 1개 / 정렬 여부는 못 물음 → 면접관이 대신 꺼냄

**내가 말한 접근법**
"b1 또는 b2가 a 안에 있으면 겹침" → **감싸는 경우(`a={10,11}, b={9,12}`)를 놓침.**
생각은 하고 있었는데 조건이 안 떠올라서 말 안 함 → 다음엔 "이 경우가 걸리는데 조건이 바로 안 떠오릅니다"라고 **말하기**.

**배운 것**
- 구간 겹침 표준 공식: `a1 < b2 && b1 < a2` — "안 겹치는 두 경우"의 부정에서 유도
- O(n²) → O(n log n): **시작 시각으로 정렬하면 바로 앞 것과만 비교**하면 된다
- "O(n²)인데 빨라지려면?" → 첫 후보는 항상 **정렬** 아니면 **HashMap**

**잘한 것**
- 핵심 엣지 케이스(붙은 경우)를 스스로 떠올림
- (가)/(나) 중 짧은 쪽을 바로 고르고 "반대 부등호에 NOT"으로 정확히 요약
- `j = i+1` 이유, O(n²)이 문제라는 판단 정확

**보완**
- 엣지 케이스 질문이 1개로 끝남 → **"없으면 / 하나면 / 경계가 닿으면"** 을 모든 명사에 기계적으로 적용
- "정렬"이 바로 안 나옴

**다음 목표**: 코드 전에 **엣지 케이스 최소 3개** 묻기 (체크리스트대로)

## 엣지 케이스 체크리스트 (문제의 모든 숫자·명사에 적용)

```
① 없으면?        빈 배열, null, 0
② 하나면?        원소 1개, 길이 1
③ 경계가 닿으면?  같은 값, 딱 붙은 값, 최솟값/최댓값, 역순, 음수
```
